# PhoneBL/MAP 功能补全与全选设计规格

**日期：** 2026-08-31  
**项目：** `E:\MAP`
**状态：** 已获用户确认，进入实现计划阶段前的规格审查

## 目标

补齐上一轮审查中确认未完成的七项能力，并把图库中的“全选”升级为真正面向当前查询结果的跨分页选择。完成后的应用仍保持本地优先、原图不被编辑操作覆盖、现有玻璃拟态视觉方向不变。

七项补全范围：

1. XMP sidecar 写回
2. 保存搜索
3. 真正的图库虚拟滚动
4. 多图对比
5. 旅程/停留点视图
6. GPS 热力图
7. 可选本地 CLIP 语义搜索

另加：工具栏和批量栏“全选/取消全选”、Windows `Ctrl+A`、跨分页选择状态。

## 现状与约束

- 主进程为 `main.js`，渲染逻辑集中在 `renderer/app.js`，安全桥接在 `preload.js`。
- SQLite schema 已有 `saved_searches`、`xmp_synced`、相册、照片版本和 GPS 字段；应优先扩展现有接口，不重复建模。
- 项目已有 `exiftool-vendored`、Leaflet 和地图瓦片缓存能力；不新增在线地图服务依赖。
- 原图必须保持不变。XMP 功能写相邻 sidecar；修图和批处理继续写版本副本。
- 所有新功能必须在没有照片、没有 GPS、依赖不可用、查询结果为空和单项失败时给出可理解的空状态或错误，不得让渲染进程出现未处理异常。
- CLIP 是可选本地能力。未配置模型时，普通文件名/标签/日期搜索必须继续可用；照片和文本不得因 CLIP 功能自动上传。

## 方案与选择

采用分三波交付，但在同一项目和同一功能目标内完成：

### 第一波：图库基础能力

- 全选/Ctrl+A
- 保存搜索
- XMP sidecar 写回
- 真正的虚拟滚动

这些能力共享查询规范和选择模型，应先完成，避免后续对比/批处理重复解决跨分页问题。

### 第二波：地图与比较体验

- 多图对比
- 旅程/停留点视图
- GPS 热力图

这些能力复用照片查询、GPS 数据和现有 Leaflet 地图，不改变扫描数据结构。

### 第三波：本地语义搜索

- 引入可选的本地 CLIP 适配器和向量索引。
- 模型、索引和运行状态均在本机；模型不可用时显示安装/配置提示，不伪造语义结果。

这种拆分允许每一波独立运行和验证，同时避免把地图、图库虚拟化和本地模型加载耦合成一次不可诊断的大改动。

## 交互设计

### 结果集选择

渲染层维护当前查询对象：搜索词、筛选、起止日期和排序。主进程提供与 `get-photos` 使用同一过滤条件的 ID 查询接口。点击“全选”或按 `Ctrl+A` 时，选择当前查询结果的全部照片 ID，而不是只选择当前已渲染卡片。

- `Ctrl+A` 仅在照片库视图生效。
- 当焦点位于输入框、下拉框、日期控件、可编辑元素或弹窗表单时，不拦截浏览器默认行为。
- 选择结果在虚拟滚动、分页、筛选恢复和卡片重绘后保持一致。
- 查询条件发生变化时清空旧选择，避免把上一查询的照片误用于批处理。
- 批量栏显示 `已选 N 张`，按钮在“全选”和“取消全选”之间切换；单张点击可以从全选结果中移除。
- 批量操作仍通过现有选择 ID 集合执行；空结果或空选择显示明确提示。

### 保存搜索

保存搜索记录名称和查询条件快照。用户可以保存当前搜索、恢复搜索、删除搜索；重复名称给出可理解错误。恢复后自动重载图库并清理与旧查询不匹配的选择。

### XMP sidecar

对照片当前可编辑元数据执行写回：关键词/标签、评分和色标。写入目标为原照片旁边的 `<原文件名>.xmp`，成功后标记 `xmp_synced=1`；本地数据库变更但 sidecar 写入失败时保留 `xmp_synced=0` 并报告失败项。批量写回使用任务中心可观察的进度，不覆盖原图。

### 虚拟滚动

图库保留现有分页查询，但只将视口上下缓冲区的卡片放入 DOM。使用固定的卡片高度/间距计算可滚动占位空间，滚动位置决定渲染窗口；缩略图观察器只绑定当前窗口。选择集合、详情导航和批量操作不依赖 DOM 中是否存在卡片。

### 多图对比

从当前选择打开对比视图，最多展示四张。少于两张时提示用户至少选择两张；超过四张时按当前排序取前四张并告知限制。每个面板显示图片、文件名、日期、尺寸、评分、GPS 和当前版本状态，支持关闭返回图库，不修改照片。

### 旅程与停留点

旅程由有 GPS 的照片按时间排序后自动切分：相邻照片时间间隔超过 24 小时则开始新旅程。停留点由同一旅程中相距不超过 1 公里、且时间跨度不超过 6 小时的照片聚合而成。界面显示旅程日期范围、照片数、停留点数量和地图轨迹；无 GPS 照片不参与聚合，但不影响图库。

### GPS 热力图

在现有 Leaflet 地图上增加热力图模式。将 GPS 点按约 0.01 度网格聚合，按照片数量映射半径和透明度；切换普通标记/热力图不改变地图中心和缩放。无 GPS 数据时显示空状态，不请求新的外部服务。

### 本地 CLIP 语义搜索

定义本地模型适配器接口：检查模型、生成图片向量、生成文本向量、查询相似结果。模型路径和索引状态写入本地设置；首次建立索引按任务显示进度，失败项可重试。向量结果只作为搜索排序/过滤，不修改原始照片或标签。未安装模型时显示“未配置本地模型”，并提供配置入口，不把普通关键词搜索标为语义命中。

## 数据流与接口边界

1. `renderer/app.js` 生成规范化查询对象。
2. `preload.js` 暴露最小化方法：查询 ID、保存/读取/删除搜索、同步 XMP、加载旅程/停留点、加载热力图数据、比较视图所需详情、CLIP 状态和索引任务。
3. `main.js` 复用统一的照片过滤构造逻辑，保证分页数据、计数、全选 ID 和保存搜索恢复的结果一致。
4. `src/database.js` 负责必要的 schema 迁移和索引；不在渲染层直接访问 SQLite。
5. `src/metadata.js` 封装 XMP 字段映射与写入结果；`src/clip-search.js` 封装本地模型生命周期和向量存储。
6. 失败结果使用 `{ ok: false, error, failed }` 形状；成功结果带数量和可追踪状态，前端统一转为 toast、空状态或任务进度。

## 测试与验收

### 单元/集成测试

- 查询条件在分页、计数和全选 ID 接口之间一致。
- `Ctrl+A` 不影响搜索输入框和表单控件；照片库中能选中所有匹配 ID，再次操作能清空。
- 保存搜索可创建、读取、恢复和删除，非法名称与空查询有明确错误。
- XMP 字段映射、sidecar 路径、成功/失败状态和原图不变均有测试。
- 虚拟滚动在大量照片时 DOM 数量受窗口限制，滚动后选择状态不丢失。
- 对比视图验证 0/1/2/4/5 张选择边界。
- 旅程切分、停留点聚合、无 GPS 空结果和热力图网格聚合有固定样例测试。
- CLIP 未配置、索引成功、单张失败、查询为空均有测试；不得发起网络请求。

### 真实 UI 验证

在真实 Electron 窗口中验证：

- 160 张以上图库只渲染窗口卡片，滚动加载正常。
- `Ctrl+A` 选中当前搜索结果的全部照片，跨分页批处理数量正确。
- 保存搜索恢复后结果和选择状态正确。
- XMP 同步、对比视图、旅程/停留点、热力图和 CLIP 未配置状态可操作。
- 无未捕获 renderer 异常，已有地图瓦片/标记和 AI 设置冒烟检查不回归。

- `npm run lint`
